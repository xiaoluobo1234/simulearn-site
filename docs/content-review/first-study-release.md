# 首次试学与发布准备

整理日期：2026-10-25（Asia/Shanghai）。本轮继续教程模块，基于学习实验室 PR #10；没有合并生产分支、发布新内容或代替本人进行教学审核。

## 实际实现范围

- `/learning/start/` 用同一均匀轴杆连接预测、浏览器 Python 公式、双单元装配、原项目练习与证据记录。参数直接读取已有 `uniform-bar/input.json`。关联检查会比较 Python 模板输入、装配默认值和原基准三项目标量，防止入口演变后悄悄换题。
- 首页“开始学习”、项目入口与六阶段课程接入首次试学。`/labs/python/?template=bar` 仅选择站内既有模板；不运行代码、不接受 URL 中的代码或输入。重复或未知模板参数不预填。
- 试学正文只在当前页面内存中，实验链接在新标签打开。用户显式开始、手动声明和结束时才记录本机时间；修改观察会撤销相应声明和结束标记。可导出未完成 JSON / Markdown，刷新或关闭前需要自行保留文件。
- “结束本次自述”只结束记录，导出 `sessionStatus`；`learningCompletion` 始终是 `not-assessed`。受阻原因也可记录，四个勾选不代表四次运行、掌握或课程完成。执行环境空白时仍是未提供。
- 试学反馈绑定实际任务与固定内容版本，新增可选的起点、首次输出、卡点、下一步和参与者自述耗时。空缺保留 `null`；字段越界、任务/版本不符或异常值会拒绝整条导出，不截断正文。不保存、上传或自动发送反馈。
- `/content-status/` 和内容来源组件接入人工审核包。`/downloads/content-review.json` 与 `.md` 在构建时从公开源码生成，包含 24 组内容、相关正文/算法/输入/附件、逐文件 SHA-256、版本及文件集合指纹。审核人、日期、结论均留空，检查项均未审核，`publication.approved` 为 `false`。

## 试学方式

1. 从首次试学页核对均匀杆输入、方向与假设，先记录自己的预测。
2. 打开轴杆 Python 模板，核对登录与输入后显式运行，单独导出真实运行文件；失败或未运行直接记录。
3. 在装配页核对两段长度、截面、支承和载荷，再显式求解。比较端点位移、左端反力和总能量；中间节点不能额外固定。此均匀轴杆位移为一次函数，两种网格结果一致不代表一般模型已收敛。
4. 在原项目练习中使用实际取得的结果核对，留下单位、条件、环境、文件位置和下一项任务。浏览器计算、本机复现及在线 CAE 各自记录。
5. 导出自述草稿和实际实验文件。愿意提供反馈时，使用已绑定 `first-study-v1` 的反馈入口，由本人决定分享范围。

没有自动招募或联系参与者，没有收集到真实试学样本，也没有测得首次结果耗时、完成率或七日回访率。本轮开发测试与视觉操作均为合成验收，不能填入这些产品指标。

## 怎样使用人工审核包

1. 先核对包内 `sourceCommit`、`workingTree`、每项 `contentVersion` 和文件集合 `fingerprint`，确保审核的是准备发布的内容。源码或相关文件变化后重新下载并复核变化范围，旧结论不能自动沿用。
2. 先走一次均匀杆路径，核对引导、原基准、Python 和装配实验，再按清单检查基础教程、诊断和其余案例。只审核其中一部分时明确写出范围，其余继续待审核。
3. 对照各项工程条件、来源/权限、证据与隐私、具体算法检查问题，填写真实审核人、日期、结论、修订建议及实际核对范围。不要把下载模板、代码测试或参考计算当作内容审核。
4. 在对应 PR 或当前会话中明确提供审核结论与发布范围。当前网站不接收或自动采纳填好的审核包，也不会因为修改下载文件而批准发布。

文件的工作副本字节与 Git 提交字节分别登记。Windows 换行也可能导致工作树干净但字节不同；`matchesCommit: false` 不直接表示代码已修改。只有实际字节匹配时才给出对应 Git 提交的永久链接。

构建参考证据与人工审核独立。审核包检查三套参考清单是否对应当前提交、版本和相关文件；它只涉及既有三项目标量、输入指纹及参考自检，不声称逐项验证全部输出。
