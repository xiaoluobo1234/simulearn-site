# 单项内容审核工作台

整理日期：2026-10-25（Asia/Shanghai）。本轮基于 PR #13，继续教程模块的发布准备，不修改账户接口、CAE 模块或生产发布状态。

## 怎样使用

1. 从内容审核索引或文章下方的“填写本项审核回执”进入，选择本次实际核对的一项内容。每份回执只对应一项，不把其他未审核内容计为通过。
2. 对照页面、原始来源和相关文件核对，填写真实审核人、实际审核日期、核对范围，以及每项检查的结论和具体依据。姓名与日期默认空白，不从账户或设备时钟补写。
3. 可以随时导出未完成的 JSON 或 Markdown。当前输入仅在页面内存中；刷新、关闭或切换内容前，请先导出保存。
4. 总结论需要明确选择。只有审核人、日期和范围完整，且每项检查均为通过并写有依据，才能记录“本项可接受”；未核对、不适用和需修改不会自动升级为通过。发现问题时可以保留修改意见或阻碍说明。
5. 继续核对时选择自己导出的 JSON，先查看文件原文与版本匹配情况，再明确恢复。文件中的姓名、日期和结论仍是声明，不代表系统认证了审核者身份。
6. 将本人确认后的回执按原有仓库评审流程登记，或在当前会话中说明实际审核结论与发布范围。工作台不会自动发送、提交 PR、修改内容状态或批准上线。

## 回执绑定范围

回执保留原始审核依据的源码提交、构建时间和工作树状态，以及单项内容的 ID、标题、页面、版本、源码位置、文件集合指纹、逐文件路径/字节数/SHA-256 和检查问题。导出时间单独记录，不作为审核发生日期。

恢复时既比较内容指纹，也比较文件集合和检查问题。任何变化都使该回执不能应用到当前版本；仅预览旧记录，不覆盖现有草稿。若只是其他文件改变了源码提交，而本项所有绑定信息仍一致，可保留原依据继续记录，同时显示当前构建提交供核对；不会把历史结论冒充新一轮审核。

修改实际范围、检查依据或其他审核字段后，需要重新明确记录总结论。读取文件、下载模板、代码测试通过与填写回执分别记录，不相互推导。

## 保存与验收边界

- 文件在本机读取，最多 2 MiB。未知格式、版本、非法字段、超限文字或损坏 UTF-8 会拒绝，保留当前输入；不截断审核依据。
- 预览不修改当前稿；正文变化、选择其他内容、新建、取消或被后一次读取替代时，旧预览失效。未编辑的多行原文在恢复与导出时保留换行格式。
- 原文件指纹只标识文件字节，不证明来源或经历真实。页面不读取私人学习记录，不执行导入代码，不保存到浏览器存储，也不向服务器提交回执。
- JSON 与 Markdown 是本地工作文件，可能包含审核人和私人备注，分享前需要本人核对范围。来源链接仅使用当前构建中的公开条目，不采用导入文件提供的链接。
- 即使填写了可接受的总结论，回执的发布批准仍为 `false`，原公开目录仍保持待人工审核。正式内容审查与发布继续遵守根目录 `AGENTS.md`。

开发测试会使用合成姓名、日期和核对意见验证软件行为，不构成真实人工审核，也不能写入教学内容的审核状态。最终单元、浏览器及远端构建结果见本轮 PR。
